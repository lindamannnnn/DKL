# DKL · AI 辅助信奥学习平台

> 一个面向 4-6 年级小学生的 C++ 信奥自学平台 —— 把「模糊的教培需求」拆解成「可上线的 AI 教学系统」的完整实践。
>
> 本文档面向 **FDE（Forward Deployed Engineer）岗位** 的能力展示：不止于"做了什么功能"，更侧重"如何在模糊需求下拆解问题、把 LLM 安全地落地到真实教学场景、并用一套可复算的评测体系保证质量"。

---

## 一句话定位

**DKL = Markdown 课件渲染引擎 + 在线判题（IOI 部分分）+ AI 竞赛教练 + 可复算的课程质量评测体系。**

它解决的真实问题是：**一个不懂 C++ 的家长/机构，如何让一个小学生在家系统、正确地学完 GESP C++ 1-8 级？** —— 这是一个典型的"客户手里只有模糊目标，没有清晰规格"的场景。

---

FDE 的核心不是写代码，而是**在模糊、半结构化的真实需求里，端到端地把系统交付上线并对结果负责**。这个项目里，我对标了 FDE 的四项关键能力：

| FDE 考察点 | 本项目的对应实践 |
|---|---|
| **问题拆解**（把模糊 brief 拆成可交付计划） | 把"让小学生自学信奥"拆解为 7 个 Phase（基础设施→后端→前端→评测→AI→激励→题库），每个 Phase 有可验证的完成标准 |
| **AI/LLM 生产落地**（非玩具，含安全与幻觉控制） | AI 教练不是裸调 API：规则引擎兜底编译错误 + 事实知识库拦截高频语法问答 + 严格系统提示词（防超纲/防给答案/防说反）+ 温度分级 |

| **交付与责任**（部署、数据、边界情况） | Docker Compose 一键起全栈（PG/Redis/JudgeServer）、多租户数据隔离、未成年人隐私考量、题库数据流水线（抓取→清洗→分级→导入→验证） |

## 三个最能体现工程判断的模块

### 1. AI 教练：把"会胡说的大模型"驯化成"可信赖的小学老师"

这是本项目最有 FDE 含金量的部分。**直接裸调 LLM 教小学生是危险的**——实测发现 AI 会：把 `cin`/`cout` 操作符方向说反、直接给完整答案、编造语法规则、超前讲解没学过的内容。对教学场景，这些都是不可接受的。

我设计的**三层防线**：

```
学生提问 / 提交错误代码
        │
        ▼
┌─────────────────────────────┐
│ Layer 1: 事实知识库          │  高频语法问题（cin/cout、头文件、分号…）
│ aiKnowledgeBase.ts          │  命中 → 直接返回标准答案，不调 LLM
└─────────────┬───────────────┘  （根治"简单问题胡说"）
              │ 未命中
              ▼
┌─────────────────────────────┐
│ Layer 2: 编译错误规则引擎     │  15+ 确定性错误模式匹配
│ errorRules.ts               │  编译错误不走 LLM，给出确定事实
└─────────────┬───────────────┘  （快、准、稳定）
              │
              ▼
┌─────────────────────────────┐
│ Layer 3: LLM + 严格护栏      │  系统提示词含"事实准确性最高优先级"
│ aiFeedbackService.ts        │  · 知识点白名单 + 课时上下文注入（防超纲）
│  温度 0.3（批改）/0.7（聊天） │  · "不确定就承认"机制（防编造）
└─────────────────────────────┘  · 只给思路不给完整代码（防抄答案）
```

**关键决策**：规则引擎只把"错误原因"传给 LLM，**不把"修复建议"传给 LLM**——避免 LLM 复述完整修复代码、违反"不给答案"的教学原则。

**结果**：端到端测试下，高频语法事实 100% 准确（走知识库），不再出现完整题解泄露，反馈长度控制在 3-4 句（匹配小学生阅读耐力）。

### 2. 评测体系：用"虚拟学生"客观测量课件质量（Evals Engineering）

课件质量不能只靠"我觉得不错"。我建立了一套**有证据锚点的测量体系**，这是本项目最接近 FDE"evals"要求的部分：

- **双智能体学生人设**：一个"零基础小白"、一个"略有基础"，模拟真实学生的理解边界。
- **客观测量准则 v1**（`docs/agents/evaluation-rubric-v1.md`）：明令禁止"凭感觉打分"，每条结论必须能回答"证据在第几页/第几行/哪道题"。
- **闭卷独立完成测试**：测"学生能否独立解题"时**必须遮住示例代码**（看着示例写等于没测），用 ✅/🟡/❌ 三级判定 + 明确公式计算完成度。
- **逐课评测报告**：GESP 1 级 18 课、GESP 3 级 20 课均产出逐课报告（`docs/reports/`），驱动了多轮课件修复（如剔除超出认知的"前缀和"、把"数组下标从 0"统一为"从 1"等真实教学问题）。

> 这套体系的本质是：**把"课件好不好"这个主观判断，变成可复算、可回归、有失败模式目录的客观工程。** 这正是 FDE 在 AI 项目里最被看重的能力。

### 3. 判题系统：IOI 部分分制 + 题库数据流水线

- **IOI 部分分**：每个测试点独立计分，返回逐测试点结果（AC/WA/TLE/MLE/RE），而非"全对或全错"——更符合竞赛教学需求。
- **题库流水线**：从多个公开 OJ 源（东方博宜 1042 / 一本通 / CSP 真题等）抓取 → 清洗（修复 markdown 转义、in/out 配对、`.ans` 兼容）→ 按 GESP 1-8 级分级 → 幂等导入 → 校验脚本验证。当前库内 1500+ 道带测试数据的可判题。

## 数据模型（多租户，16 张表）

```
Tenant ── User ── Class ── ClassStudent / ClassCourse
                │
Course ── Chapter ── Lesson ── LearningProgress
                          │
Problem ── TestCase ── Submission（含 AI 反馈 aiFeedback）
Exam ── ExamProblem ── StudentExam
AIConversation / FeedbackReport / Achievement / UserAchievement / Mistake
```

- **所有业务表含 `tenant_id`**：通过 `X-Tenant-Id` Header / JWT 实现多机构数据隔离——这是 SaaS 交付的基本要求。
- `TestCase.score` 字段支撑 IOI 部分分；`Submission.aiFeedback` 落库 AI 点评，便于复盘。

## 技术栈与运行

| 层级 | 技术 |
|---|---|
| 前端 | React 18 · TypeScript · Vite · Tailwind · Monaco Editor |
| 后端 | Node.js · Express · Prisma · PostgreSQL |
| 缓存 | Redis |
| 判题 | JudgeServer（Docker 沙箱，IOI 部分分） |
| AI | OpenAI / DeepSeek / Kimi（三层护栏架构） |

**本地一键起全栈**（需先启动 Docker Desktop）：

```bash
docker compose up -d          # PostgreSQL + Redis + JudgeServer
cd server && npm install && npx prisma migrate dev && npx prisma db seed && npx tsx src/index.ts
cd client && npm install && npx vite --port 3000
```

|---|---|---|
| 前端 | http://localhost:3000 | 学生 `student@dkl.local / 123456` |
