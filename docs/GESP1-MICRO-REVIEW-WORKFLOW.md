# GESP1 微课改造与三轮评审流程

> 把 GESP1 现有课件（02-12 课）按第 1 课的儿童自学微课格式改造，每课经过"改写 → 测评 → 修改"三轮闭环，确保小学生能独立看懂。

---

## 一、流程图

```
原始课件
   ↓
[改写] → 按 MICRO_LESSON_FORMAT.md 拆分为 story/card/demo/checkpoint/challenge
   ↓
[第1轮测评] → 小学生智能体"小柯"学习新课，输出报告
   ↓
[第1轮修改] → 修复报告中的"必须修改"项
   ↓
[第2轮测评] → 小柯再次学习，验证问题是否解决
   ↓
[第2轮修改] → 修复剩余问题
   ↓
[第3轮测评] → 小柯最终评审
   ↓
[第3轮修改] → 微调、润色
   ↓
导入数据库 → 前端验证 → 进入下一课
```

## 二、改写标准

### 2.1 必须包含的元素

| 元素 | 说明 | 最少出现次数 |
|------|------|-------------|
| story | 故事化开场，引出本课问题 | 1 次 |
| card | 知识卡片，一页一个概念 | 每页必须有 |
| demo | 可运行代码示例 | 每个知识点至少 1 个 |
| checkpoint | 检查点/quiz | 每个知识点后 1 个 |
| challenge | 课堂小挑战 | 至少 2 个 |
| hint | 小贴士/常见错误提示 | 至少 1 个 |

### 2.2 格式规范

- 一个 `## ` 标题 = 一页
- 每页正文不超过 3 行
- 新术语必须有比喻或例子
- 代码不超过 8 行，有中文注释
- 选择题选项必须每行一个
- 课后操作题用 `<!-- problem: gesp1-XX-NN -->` 占位

### 2.3 顺序要求

```
故事开场 → 前置知识回顾 → 新概念讲解 → 代码示例 → 检查点 → 挑战 → 总结/小贴士
```

特别注意：
- 代码示例前必须先讲操作步骤（如何打开 Dev-C++、保存、运行）
- 检查点问到的术语，前面必须解释过
- 新概念必须从旧知识自然过渡，不能跳跃

## 三、测评触发方式

调用 `.kimi/skills/course-kid-evaluator/SKILL.md`：

```text
请用小柯的身份评测 server/courses/gesp1-micro/XX-标题.md
```

测评时必须：
1. 读取 `references/kid-persona.md`
2. 读取 `references/knowledge-state.md`（累积知识状态）
3. 输出儿童视角报告
4. 更新 `knowledge-state.md`

---

## 四、修改优先级

按测评报告中的问题，按以下优先级修改：

1. **P0 - 知识跳跃**：新概念没有解释或没有过渡
2. **P0 - 顺序错误**：代码/操作步骤顺序颠倒
3. **P1 - 术语未解释**：专业词没有儿童化说明
4. **P1 - 缺少互动**：一页只有文字没有 checkpoint/challenge
5. **P2 - 表达冗余**：句子太长、太抽象
6. **P2 - 视觉优化**：emoji、表格、提示框的使用

---

## 五、三轮评审通过标准

### 第1轮：大问题必须改
- 没有知识跳跃
- 顺序正确
- 所有检查点用到的术语都已解释

### 第2轮：小问题必须改
- 表达清晰
- 互动充足
- 小柯能独立答对 80% 以上 checkpoint

### 第3轮：体验优化
- 小柯愿意继续学下一课
- 没有明显困惑点
- 完成度达到 90% 以上

### 最终验收清单

- [ ] 小柯能说出本课学习目标
- [ ] 小柯能独立运行示例代码
- [ ] 小柯能答对所有 checkpoint
- [ ] 小柯能完成所有 challenge
- [ ] 小柯没有出现"知识跳跃点"
- [ ] 小柯的平均求助次数 ≤ 1 次
