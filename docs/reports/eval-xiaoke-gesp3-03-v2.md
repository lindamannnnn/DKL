> 本次带着 GESP2 毕业 + GESP3-01（一维数组）+ GESP3-02（数组增删）的知识盲测，未参考任何旧报告。

## 逐页第一反应（按 `## ` 分页，边看边记）

- **P1 目标**：`cnt[x]++` 是什么意思？"票王"听起来好玩。
- **P2 故事**：选班长数票数得眼花，老师说"票上写几号就扔进几号桶"——这个办法我听完就想拍桌子：太聪明了！
- **P3 回顾**：第 1 课的遍历、第 2 课的增删逆序都记得。"以前要一个个比较，今天有妙招"，期待。
- **P4 下标当桶用**：`cnt[v]` 表示"值 v 出现了几次"，读到 x 就 `cnt[x]++`——往 x 号桶投球⚽。等等，下标不是"第几个柜子"吗？现在下标直接是"值"？盯着 `cnt[a[i]]++` 看了两遍：a[i] 是 3，就去 cnt[3] 加一……懂了！柜子编号就是票上的号码！不过 demo 里 `for (int i = 0; i < 6; i++)` 从 0 开始——第 1 课不是说"比赛从 1 用"吗？这里又从 0 数了，两种用法换来换去我有点嘀咕。
- **P5 检查点**：`{2,1,2,1}` 里 1 出现 2 次，c[1]=2，选 B。✅
- **P6 桶要先清空**：全局自动清 0（第 1 课学过）；值最大 100 就开 `cnt[101]`，下标 0~100——和第 1 课"多留余量"一个意思。值上亿开不下就不能用，记住了。
- **P7 检查点**：选 B，`cnt[101]`，因为值可能是 100。✅
- **P8 什么时候能用**：三关——值域别太大、必须是整数、个数随便。"小数不能当柜子编号"这个解释很形象，cnt[3.5] 确实没有 3.5 号柜哈哈。10⁶ 这个写法旁边标了"一百万"，贴心。
- **P9 检查点**：选 A，成绩 0~100 分最适合；身份证号太大，小数没法当下标。✅
- **P10 谁是票王**：扫一遍桶，球最多的桶的编号就是票王——还是打擂台！`cnt[v] > cnt[ans]` 这个写法妙：擂台比的是"桶里的球数"，记的是"桶的编号"。我想了一下才转过弯，转弯过程自己能完成。
- **P11 检查点**：`2 1 2 3 2`，2 有 3 票，选 B。✅
- **P12 桶排序**：从小到大开桶，桶里有几个球就把编号输出几次，倒出来自动排好队⚡。demo 里 `while (cnt[v]--)`——GESP1-15 学过 `while (t--)` 循环 t 次！老知识用上了，看得懂。
- **P13 检查点**：`3 1 4 1 5` 倒出来 `1 1 3 4 5`，选 B。✅
- **P14 计数法有多快**：一趟遍历 vs 双重循环，10 万次 vs 100 亿次，一眨眼 vs 一分多钟——对比很震撼，我懂了"为什么这招快"。但是 **O(n+V)** 和 **O(n²)** 这两个写法没人解释，像密码。我知道它在说"操作次数"，可 O 是什么意思呀？跳过去了。
- **P15 检查点**：选 A。✅（凭"10 万 vs 100 亿"记住的）
- **P16 挑战1 统计票数**：闭卷写：全局 `cnt[105]`，读 n，边读边 `cnt[x]++`，再 1~100 扫一遍，`cnt[v] > 0` 就输出 `v << " " << cnt[v]`。对答案：一致。✅
- **P17 挑战2 票王**：闭卷写：统计完打擂台，`if (cnt[v] > maxC) { maxC = cnt[v]; ans = v; }`。"并列输出最小的"→ 用 `>` 不用 `>=`，从小往大扫先到先赢——和第 1 课"相同最大值留第一个位置"一个道理！对答案：一致。✅
- **P18 挑战3 数字去重**：闭卷时我用的是 cnt 桶：`if (cnt[x] == 0) { cout << x << " "; cnt[x]++; }`。对答案：示例用 `bool seen[105]` 当"签到表"，见过打勾——比我的 cnt 更省，思路一样。✅（两种都会了）
- **P19 挑战4 区间计数**："前缀和"第一次见！`sum[v]` = 值 ≤ v 的有几个，像一层层叠台阶。回答 [l, r] 只要 `sum[r] - sum[l-1]`。**可是 demo 有问题**：题目说要读 n、读数组、还要读"2"个提问再分别回答，demo 却把数组写死在代码里、只算了一个 `sum[3] - sum[0]`，根本没有读输入！闭卷时我按题面自己写：先 `cnt[x]++` 统计，然后每个提问 [l,r] 我就 `for (v = l; v <= r; v++) total += cnt[v]`，笨办法但能做出来，样例 `1 3`→4、`3 5`→4 都对。看完示例才明白前缀和是"问一万次也不怕"的加速办法——`sum[r] - sum[l-1]` 一次减法。方法我看懂了，台阶比喻也想得通，但没有自己独立写过一遍，心里不算踏实。
- **P20 小贴士**：三条都中要害，尤其"x 是值不是第几个"。
- **P21 课后挑战**：做题去！

## 必须修改的问题（按优先级）

1. **挑战4 demo 与题面不符（P0）**：题面要求读 n、读数组、读 q 个提问并逐个回答，demo 却写死数组、不读任何输入、只输出一行 `sum[3] - sum[0]`。学生无法从示例学会"如何读入询问并循环回答"，前缀和这个新概念的唯一示例是半成品。建议补全为完整可提交的程序。
2. **前缀和无专门卡片和检查点（P1）**：新概念藏在挑战里，没有 checkpoint 验证（例如"sum[5] - sum[2] 表示什么？"），学生容易"看懂了但不会用"。
3. **O(n+V) / O(n²) 记号无解释（P2）**：第 14 页出现得突兀。建议写成"有个记号叫大 O，先混个脸熟就行"或者干脆只用"约 n+V 次"的说法。
4. **0 基/1 基下标再次混用（P2）**：第 4、10、12 页 demo 用 `for (i = 0; i < 6; i++)`，与第 1 课"比赛从 1 用"口诀冲突，建议统一或说明"demo 数组写死时从 0 数也行"。
5. **课后题5"查找含有x的数"题面 HTML 损坏（P1）**：`1<del>9999之间的数`、`1</del>9之间的一位数` 删除线标记未闭合，数值范围读不出来，只能靠样例猜。建议修复题库中该题的 input_desc。
