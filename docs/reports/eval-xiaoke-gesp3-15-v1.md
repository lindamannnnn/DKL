## 逐页体验记录

### 页0 标题 + 目标
"原码、反码、补码"——三个名字都没听过。"知道负数在电脑里怎么存"，这个问题我从来没想过，有点好奇。

### 页1 故事：负数怎么存？
"电脑里只有 0 和 1，连减号都没有"——对哦！我写下 -5 的时候，减号放哪里呢？"当一回科学家"这个说法我喜欢。想往下看了。

### 页2 回顾
8 位二进制能表示 256 种状态，`00000101` 是 5——14 课刚学过进制转换，我还记得短除法。衔接很顺。✅

### 页3 卡片：符号位
"最左边那位叫符号位：0 表示正数，1 表示负数"——这个我懂，像给数挂一个"正/负"的小牌子。
可是"**机器数**"和"**真值**"把我卡了一下："这样存起来的数叫机器数，它真正代表的数值叫真值"——"真正代表的"是什么意思呀？我对着例子想了一会儿才明白：`10000101` 这串 0 和 1 是机器数，它表示的 -5 是真值。想通了，但这句话我得读三遍。
demo：把 5 转成 8 位二进制字符串。`s = (char)('0' + n % 2) + s` 这种"往前面拼"的写法 14 课见过，能看懂。核心 4 行，不累。

### 页4 检查点：符号位
`10000101` 最高位是 1 → 负数，选 B。✅ 秒答（页 3 刚讲，规则只有一句话）。

### 页5 卡片：原码
"符号位 + 绝对值的二进制"，+5 和 -5 只差最左边一位——好懂！"0 有两种写法"这个缺点我也看明白了：`00000000` 和 `10000000` 都是 0，确实奇怪。但"原码直接做加法会算错"**没有给例子**，我想不通为什么会算错，先标记在这里。
demo 核心 5 行，能看懂，就是上一页 demo 改了一点点。

### 页6 检查点：原码找找看
-3：符号位 1 + `0000011` = `10000011`，选 A。✅ 我在纸上拼了一遍，没错。

### 页7 卡片：反码
"负数：符号位不动，其余每一位 0 变 1、1 变 0"——规则一句话，例子 `10000101` → `11111010` 我对着逐位检查了 8 位，全对。✅ 这页是我最顺的一页。
demo 核心 4 行，`for (char c : v)` 这种写法 12 课模拟算法学过，不慌。

### 页8 检查点：反码怎么变
符号位不变，选 A。✅ 秒答。

### 页9 卡片：补码
"补码 = 反码 + 1"——规则简单。但"+5 和 -5 的补码加起来正好是 `00000000`（多出来的进位扔掉）"这句，我在纸上列竖式加了一遍：`00000101 + 11111011`，从右往左进位……真的是 9 个位全满然后多出一位扔掉变 8 个 0！好神奇，我算了大概两分钟，算对的时候很开心。这是本课我最有成就感的一刻。
demo 是"二进制加 1"的进位循环：`for (int i = 7; i >= 1 && carry; i--)`——这个循环我要很小心地读：从右往左，遇到 0 变 1 就停，遇到 1 变 0 继续。核心 6 行，但每一行都很密。我**不确定自己闭卷能不能写出这个循环**，先标记。

### 页10 检查点：补码推一推
-6 的反码 `11111001` + 1：最后一位 1+1=0 进位，倒数第二位 0+1=1，得 `11111010`，选 A。✅ 列竖式算的，没猜。

### 页11 卡片：补码的本领
三个超能力：0 只有一种写法✅懂；加减法统一——"减去一个数 = 加上它的补码"，半懂（为什么这样就对了？没说原因，我信了但心里有个小问号）；8 位补码 -128~127，负数多一个——因为 0 省出来一个位置，懂。
最后一句"这就是为什么 `int` 的范围是 -2147483648 ~ 2147483647"——哇，GESP1-02 老师说"超过 21 亿要用 long long"，原来那个 21 亿是这么来的！这个连接我喜欢。
demo 里 `a + 1` 变成 -2147483648，注释说"溢出啦"——"**溢出**"这个词第一次出现，靠注释"绕回最小值"猜懂了：装满了就绕回去。算半个新词。

### 页12 检查点：int 最小值
选 A。✅ 但是……B"电脑有时候会算错"和 C"负数比正数更重要"一看就不对，我**不用真的懂也能选对**。这题测不出我懂不懂。

### 页13 挑战 1：补码转真值
**闭卷三步法**：
1. 闭卷：输入 `11111011`。我先想：符号位是 1，是负数。小贴士口诀说"取反再加 1 得到绝对值"。我的计划：后 7 位用 14 课的 `v = v * 2 + (s[i] - '0')` 求值……不对，那是直接把补码当普通二进制。我走口诀路线：把 8 位全取反得 `00000100`，加 1 得 `00000101` = 5，输出 -5。思路通了！但写代码时卡在"字符串怎么加 1"——就是页 9 那个进位循环，我闭卷写了两次都不对（进位停不下来），**偷看了一眼页 9 的 demo** 才写出来。后来对答案发现示例用的是"v - 128"的捷径，比我少一个循环。
2. 对答案：思路不同（我：取反加 1；示例：后 7 位求值减 128），但输出一致；示例更短。
3. 判定：🟡 半独立（进位循环看了 1 次示例）。
- 备注："真值"这个词页 3 只讲了一句，这里直接用来出题，我又回去翻了一次才想起意思。

### 页14 挑战 2：负数的三种编码
**闭卷三步法**：
1. 闭卷：四步链条——①`-n` 转 7 位二进制（短除法，14 课会）②原码 = "1" + v ③反码逐位取反 ④补码 = 反码 + 1。前三步我独立写出来了！第四步又卡在进位循环，还是页 9 那个坎，再看了一次示例。示例把三步拼在一起，还用了 `for (int t = -n, i = 0; i < 7; i++, t /= 2)` 这种一行塞三件事的写法，我读不太惯，我自己写会拆成三行。
2. 对答案：逻辑一致；我的代码行数更多但更清楚；差异主要在写法风格。
3. 判定：🟡 半独立（同一处知识缺口：二进制 +1 进位循环，看了 1 次示例）。

### 页15 小贴士
两句口诀都好记："正数三码合一""负数反码 = 符号位不动其余取反，补码 = 反码 + 1"。我抄到小本本上了。✅
