## 逐页学习日记

- **故事：负数怎么存** — 对啊！电脑里连减号都没有，-5 怎么办？这个问题我自己也想过，一下子被勾住了。
- **回顾** — 14 课刚学完二进制，2⁸=256 我知道是 8 个 2 相乘（14 课的 2³ 教过我这种写法）。
- **符号位** — 最左边那位当"正负门牌"：0 正 1 负。机器数和真值两个新词，各给了一句话定义，能接住。
- **原码** — 符号位 + 绝对值的二进制，-5 就是 `10000101`，好懂！demo 正好 7 格短除法（14 课刚学），前面拼 "0" 或 "1"，看得懂。
- **反码** — 负数：符号位不动，其余 0 变 1、1 变 0。规则一句话，checkpoint 做对。**可是 demo 又是 `for (char c : v)`**（第 4 次见了！），三目运算符我会，范围 for 还是只能靠猜。
- **补码** — 反码 + 1！+5 和 -5 的补码加起来正好是 0（多出来的进位扔掉），这个"魔术"我验算了一下：00000101 + 11111011 = 100000000，8 位装不下最高的 1，扔掉就是 00000000。哇，真的！checkpoint -6 的补码我推对了。**demo 的进位循环 `for (int i = 7; i >= 1 && carry; i--)` 有点挤**：carry 是整数怎么也能当条件？GESP2-06 见过"整数当开关"，我还是不习惯。
- **补码速推法（复测重点：法二）** — 从右往左找第一个 1，这位不变，左边非符号位全取反。我照 -5 的例子推了一遍：10000101 → 最右边的 1 不动 → 左边 000010 全反成 111101 → 11111011，和"反码+1"一样！checkpoint -6 我也推对了（10000110 → 倒数第 2 位的 1 不动 → 左边 00001 反成 11110 → 11111010）。**为什么这两条路一定一样？**老师说"算出来一模一样"，没说原因，我当口诀背下来了。
- **补码的本领** — 0 只有一种写法、减法变加法、-128~127 负数多一个。最后说"这就是 int 范围是 -2147483648~2147483647 的原因"——GESP1-02 我背的"21 亿"终于知道来历了，这节课最爽的一页！demo 里 `a + 1` 变成 -2147483648，"溢出"这个词第一次见，靠注释"绕回最小值"猜到意思。
- **挑战 1 补码转真值** — 闭卷：我没走 demo 的 `v - 128`，我用速推页学的办法——把 8 位全滚雪球算出 V（11111011 = 251），符号位是 1 就减 256：251 - 256 = -5，对了！教师卡的"为什么是减 128"那段代数（"补码 = 256 + 真值"）我读了两遍没完全消化，字母套字母像绕口令。
- **挑战 2 负数的三种编码** — 闭卷：7 位短除法出数值（14 课）→ 原码拼 "1" → 反码用下标循环逐位翻 → 补码我耍了个小聪明：速推页 demo 教过 `-5 存的是 256-5`，那我直接算 `256 + n` 的二进制不就行了！三行全对。**demo 正文那段进位循环 `for (int i = 7, c = 1; i >= 1 && c; i--) { ... }` 一行干四件事，还有 `for (int t = -n, i = 0; ...)` 一次定义两个变量，我都读得磕磕绊绊。**

## 知识状态更新（本课新增）

- 符号位：最左边 0 正 1 负；机器数（存的串）vs 真值（真正的数）。
- 原码 = 符号位 + 绝对值二进制；缺点：0 有两种写法、直接加法会错。
- 反码：正数同原码；负数符号位不动、其余全取反。
- 补码：正数同原码；负数 = 反码 + 1（电脑真正用的）。
- 补码速推法二：从原码从右往左找第一个 1，该位不变、左边非符号位全取反（会推，为什么等价没讲，当口诀）。
- 补码求真值：8 位全滚雪球得 V，符号位 1 → V - 256（自己从速推页 demo 悟的替代路线）。
- 补码三本领：0 唯一、减法变加法、8 位范围 -128~127（负数多一个）；int 范围 -2147483648~2147483647 的来历（32 位补码）。
- 溢出：最大值 +1 绕回最小值（见过 demo，没正式定义）。
- 能做：补码转真值、负数三码推导、32 位二进制折半交换（字符串补足+substr 交换+滚雪球，long long 需提醒）、二进制 0/1 计数（记得处理 n=0）。
