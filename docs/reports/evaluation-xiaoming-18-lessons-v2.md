# 小明（五年级中等生）GESP1 18 课学习评估 v2

## 评估说明

- **评估人视角**：严格扮演 `docs/agents/xiaoming-persona.md` 中的 11 岁五年级小学生小明。
- **学习顺序**：按 01 → 18 顺序逐课学习，新知识必须建立在前面课程已掌握的基础上。
- **评估重点**：每节课的「新授课」部分与「课后挑战」部分；对特别长的课程只看核心新知和综合练习。
- **理解率定义**：0–100%，表示小明**真正理解**这节课核心内容的比例，不是「看完」或「复制运行通过」。
- **通过标准**：70% 表示大部分核心概念懂了，但细节或综合题可能卡壳。

## 逐课理解率

| 课号 | 标题 | 理解率 | 关键问题 |
|------|------|--------|----------|
| 01 | 走进 C++ | 65% | 课程太长（416 行/约 15 分钟），超过 5 分钟注意力极限。`#include`、`using namespace std;`、`return 0;` 被当成「魔法咒语」照抄，不理解为什么必须写。`=` 不是数学里的等于，而是「放进去」，概念转弯大。整数除法 `5/2=2` 与计算器结果冲突，容易慌。 |
| 02 | 整数运算 | 60% | 变量命名规则（不能用中文、不能数字开头、不能空格）记不住。`%` 取余能懂，但三位数拆分成个/十/百位需要连续 `%10` 和 `/10`，多步骤组合后只剩「复制示例」水平，独立写不出来。 |
| 03 | 小数运算 | 58% | `fixed` + `setprecision` 区分「有效数字」和「小数位数」太抽象，实际做题时经常只写 `setprecision(2)` 导致输出 `3.1` 而非 `3.14`。`(double)a / b` 的「小数外套」比喻能背，但不知道为什么必须加。`#include <iomanip>` 总忘。 |
| 04 | 练习课：计算小达人 | 65% | 作为复习课内容合适，但平均气温题仍会把 `total / 3` 写成整数除法，看到小数丢失会懵。没有新知，只是前 3 课薄弱点的综合暴露。 |
| 05 | 分支入门 | 72% | `if` 像门、`if-else` 像岔路的比喻很直观。关系运算符基本能懂，但 `==` 和 `=` 极易写反，第一次报错会烦躁。奇偶判断、倍数判断能照猫画虎完成。 |
| 06 | 双路分支 | 70% | `if-else` 已学过，理解较深。嵌套 `if`（if 里再写 if）需要看缩进，大括号一多就容易配对错误，独立写嵌套会卡。 |
| 07 | 多路分支 | 68% | `if-else if-else` 的「排队上车」比喻好，但条件顺序为什么不能从低到高理解不透，实际写时会把 `>=90` 放在 `>=60` 后面导致高分被截胡。`&&` 能懂，但和 `||` 混用会错。 |
| 08 | 练习课：分支大冒险 | 60% | **检查点 2 答案标记错误**：题目问「a>0 并且 b>0」应写什么，正确答案是 `a > 0 && b > 0`，但课程里标记答案为 B（`||`）。小明选 A 会被判错，非常打击自信，也会学混 `&&`/`||`。此外，第 4 关把 if-else 写成无大括号的一行，和之前教的写法不一致，会懵。 |
| 09 | 字符类型与 switch | 58% | 字符用单引号、字符串用双引号容易混。字符 `'5'` 和数字 `5` 不一样理解不透。大小写转换靠「加 32 / 减 32」像背口诀，不知道为什么。`switch` 语法新、`break` 会漏写、`default` 含义抽象，很容易复制后改不对。 |
| 10 | for 循环 | 68% | `for` 三部分的语法能记住，但 `i++`、`i--` 这种简写需要适应。循环里套 `if` 挑偶数能懂。`sum = sum + i` 这种「自己加自己」的累加概念是首次出现，虽然用「桶装石头」比喻，但独立写 1+2+…+n 仍会卡。 |
| 11 | 循环控制 | 62% | `break` 和 `continue` 的区别容易搞反，虽然用跑步比喻，但做题时仍会出现「想跳过却直接退出」的情况。中间条件为空的 `for(;;)` 配合 `break` 太抽象，一旦漏写 `break` 就是死循环，看到黑框不动会慌。 |
| 12 | 练习课：循环闯关 | 72% | 复习课，内容集中在 for、break、continue，没有新难点。找第一个被 7 整除的数需要 `for` 空条件 + `break`，部分同学仍需要对着示例抄。 |
| 13 | 求和计数 | 60% | 循环输入求和、计数能懂。求平均时的 `(double)sum / n` 转换又忘。最大值「先把第一个数当老大再逐个比较」是新的算法思维，缩进和大括号一多就乱。最小值同理。求因子和把 `%`、循环、累加混在一起，独立做困难。 |
| 14 | while 循环 | 65% | `while` 语法比 `for` 简单，但「先读一个数再进入循环、循环里再读下一个」这种哨兵模式（输入 0 停止）和 `for` 习惯不同，容易写成死循环或漏读第一个数。 |
| 15 | 短除法 | 63% | `%10` 取个位、`/10` 去掉个位经过前面复习已较熟。数位和、数位乘积能模仿。但「判断数字里有没有某个数字」需要引入 `bool found` 标志位 + `break`，步骤多，容易漏。统计出现次数需要 `count++` 和拆位同时控制，独立写不出来。 |
| 16 | 练习课：数字拆解与统计 | 75% | 复习课，核心是把 sum=0、product=1、拆位 `/10` 等套路再练一遍。因为前面刚学过，短时记忆还在，完成度较高。 |
| 17 | C 风格输入输出 | 55% | 本课最难。`printf`/`scanf` 突然出现大量符号：`%d`、`%f`、`%lf`、`%c`、`%02d`、`%.2f`。`scanf` 变量前要加 `&` 完全像背规则，不理解「地址」是什么。`scanf` 读 double 用 `%lf`、`printf` 输出 double 用 `%f` 非常容易混。时间换算的多步算术也会卡。 |
| 18 | 练习课：GESP1 综合大闯关 | 72% | 综合复习课，单知识点检查点都能过。但 5 道终极挑战题需要同时调用分支、循环、拆位、格式化输出，若前面某课薄弱（尤其 09、13、15、17）会连锁卡壳，基本靠模仿示例完成。 |

- **平均理解率**：**65%**（18 课总分 1168 / 18）

- **低于 70% 的课程**：01、02、03、04、08、09、10、11、13、14、15、17（共 12 节，占 67%）

## 最重要的修改建议

1. **立即修正课程 08 检查点 2 的错误答案标记**
   该题正确答案应为 `a > 0 && b > 0`（选项 A），课程里却标成了 B（`||`）。这会让小明明明做对了却被判错，严重打击自信心，还会把「并且」和「或者」学混。

2. **把超长课程拆成更小的关卡，并增加进度/奖励反馈**
   01、03、09、13、17 等课超过 300 行，远超小明 5 分钟注意力极限。建议每 3–4 个卡片就插入一个「小关卡完成」动画或经验条，让学习像游戏闯关一样有节点感。

3. **减少「先照抄，不用懂」的魔法代码**
   `using namespace std;`、`#include <iostream>`、`return 0;` 在第 01 课就被要求照抄，小明会一直把它们当咒语。建议用更形象的比喻（如「这是程序的身份证，每次都要带」），或把部分细节推迟到后面再解释，而不是直接说「现在照抄就行」。

4. **为抽象概念增加「一步一步跟我做」的可视化演练**
   `sum = sum + i` 的累加、`(double)a / b` 的类型转换、max/min 的「换老大」算法、拆位短除法，都需要逐行表格或动画演示变量变化。只靠文字和示例，小明会复制但不懂为什么这样写。

5. **把 C 风格输入输出（第 17 课）提前分散到前面课程中，或大幅降低密度**
   一节课内同时引入 `printf`、`scanf`、`&`、多个占位符和格式控制，信息量过大。建议把 `%d`/`%f` 提前在合适场景（如保留小数、补零排名）中少量渗透，第 17 课只作为「另一种写法」复习，而不是一次性硬塞。
