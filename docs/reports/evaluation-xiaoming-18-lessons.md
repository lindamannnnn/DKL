# 小明（五年级中等生）GESP1 18 课学习评估

## 评估说明

- **评估对象**：`server/courses/gesp1-micro/` 目录下 01~18 课 GESP1 C++ 微课。
- **评估视角**：严格扮演 11 岁五年级小学生小明（人设见 `docs/agents/xiaoming-persona.md`）。
- **学习前提**：完全零基础，不会主动查资料，遇到困难容易放弃，注意力 2~3 分钟后开始飘。
- **评估方式**：按 01→18 顺序逐课学习，带着之前学过的知识判断新课；重点估计「真正理解」而非「复制运行通过」。
- **评价基准**：70% 表示大部分核心概念懂了，但细节或综合题会卡；低于 70% 表示有重要概念没懂、课后题无法独立完成或报错会慌。

## 逐课理解率

| 课号 | 标题 | 理解率 | 关键问题 |
|------|------|--------|----------|
| 01 | 走进 C++ | 60% | 内容太满（467 行），一节课塞了骨架、变量、cin/cout、5 种运算、3 个挑战。`#include`、`namespace`、`return 0` 对零基础全是"照抄就行"，小明并不懂为什么必须写。英文单词不会读，容易把 `()` `{}` `;` 敲错。`system("pause")` 像魔法咒语，更迷糊。 |
| 02 | 整数运算 | 65% | `int` 除法"吃掉小数"能记住，但和数学课冲突时会愣住。`%` 取余能理解。拆位挑战需要 `n = n / 10` 连续改变变量，这是第一次接触"算法步骤"，小明会复制示例但说不清每一步为什么。 |
| 03 | 小数运算 | 60% | `double` 好懂。但 `fixed` + `setprecision` 要同时记两个新词 + 新头文件 `<iomanip>`，容易漏头文件。`(double)a` "穿小数外套"的比喻还行，但自己写时容易写成 `a / b` 或 `(double)(a/b)`。 |
| 04 | 练习课：计算小达人 | 65% | 复习课，概念都见过。但平均分题需要同时调动"输入→求和→转 double→保留小数"，前面有任何一处没记牢就会卡。小明会倾向于复制之前代码改数字，而不是真正理解每一步。 |
| 05 | 分支入门 | 62% | 比较运算符好懂。`if` 语法新但示例清晰。最大坎是 `==` 和 `=`，虽然课里反复强调，小明自己敲时大概率写成 `if (a = 5)`，报错后会慌。`bool` 输出 `1/0` 也有点抽象。 |
| 06 | 双路分支 | 72% | 内容和第 05 课几乎重复（if-else、奇偶、倍数、`==`/`=`），小明会觉得"这课上节课讲过"而走神。正因为重复，他反而能跟上；但作为独立一课，学习效率低，没有新成就感。 |
| 07 | 多路分支 | 60% | `if-else if-else` 结构比想象中长，大括号配对容易错。`&&` "两边都要对"好懂，但和 `%`、`==` 组合成 `n%3==0 && n%5==0` 时，符号多、括号多，小明会复制但改条件就错。条件顺序"从高到低"很重要，但容易被忽略。 |
| 08 | 练习课：分支大冒险 | 63% | 复习课提到 `&&`、`\|\|`、`!` 三个逻辑帮手，但前面只系统教了 `&&`，`\|\|` 和 `!` 没教过，小明看到会懵。示例里把 `if-else if` 写成单行无大括号形式，和前面教法不一致，容易混淆。 |
| 09 | 字符类型与 switch | 55% | 新东西太多：`char`、单引号双引号区别、字符范围比较、`+32/-32` 大小写转换、`switch`/`case`/`break`/`default`。`switch` 语法和 `if` 完全不同，break 的"穿透"概念第一次出现。`break` 在这里是跳出 switch，到第 11 课又变成跳出循环，小明会混。 |
| 10 | for 循环 | 58% | `for` 三个部分 + 分号 + 大括号是全新结构，`i++` 简写也新。"累加桶"比喻好，但 `sum = sum + i` 这种自引用式赋值需要真正动脑，小明复制能跑，自己写常忘把 `sum` 初始化为 0 或写错循环边界。 |
| 11 | 循环控制 | 52% | `break` 和 `continue` 本身不难区分，但挑战 2 出现 `for (int i = 1; ; i++)` 这种"缺条件=无限循环"的写法，课程没解释为什么空条件会永远执行。小明会照抄，但心里没底。同时 `break` 在 switch 和循环里含义不同的问题开始凸显。 |
| 12 | 练习课：循环闯关 | 58% | 复习 for、break、continue。故事里提到 while，但 while 还没教。无限 for 循环再次出现，仍无解释。小明能复制完成，但遇到稍微变化的题（如"找到第一个能被 7 整除的奇数"）不会改。 |
| 13 | 求和计数 | 55% | 一节课塞了求和、平均、计数、最大值、最小值 5 个算法模式。"把第一个数当老大"找最大值的思路好，但挑战 2 直接用 `-1000000` / `1000000` 当初始值，对小明是魔法数字；他更习惯用第一个数初始化，但两种写法都讲会让他混淆。因子和需要循环+if+%，综合性强。 |
| 14 | while 循环 | 58% | `while` 语法比 `for` 简单，但需要自己管理 `i++`，很容易忘写成死循环。"输入 0 才停止"要先读一次、循环里再读一次，这种"读-判-读"模式对小明来说很别扭，会漏掉循环外的第一次输入。 |
| 15 | 短除法 | 50% | 大量相似模式堆在一起：数位和、数位积、找数字、统计数字。`product = 1` 的初始值和 `sum = 0` 容易搞混。`bool found = false` + `break` 的组合步骤多，有一处写错就全错。短除法本身依赖 `%10`/`/10`，前面没真正理解的话这里会崩盘。 |
| 16 | 练习课：数字拆解与统计 | 55% | 复习 13-15 课。如果前面已经卡，这节课只是"再复制一遍"。统计及格人数和拆位求和都是前面原题变体，小明能跑通但独立设计循环结构困难。 |
| 17 | C 风格输入输出 | 45% | 零基础学生最怕的一课：刚习惯 `cin/cout`，突然换一套 `printf/scanf`，还要记 `&`、占位符、`%lf`（输入 double）和 `%f`（输出 double）不一致、`\n`、格式宽度。`#include <cstdio>` 且没有 `using namespace std`，和前面 16 课风格割裂，小明会怀疑"我以前是不是学错了"。时间换算综合了数学拆分 + 格式化，更难。 |
| 18 | 练习课：GESP1 综合大闯关 | 55% | 综合复习，奖杯奖励很好。但前几课欠账太多，综合题往往要同时调用多个知识点，小明会复制示例改数字，遇到题目顺序或条件变化就无从下手。 |

## 最重要的修改建议

1. **把第 01 课拆成两课，并增加"第一次运行"的图文/视频引导**
   第 01 课内容过载（程序骨架 + 变量 + 输入输出 + 运算 + 3 个挑战），远超 5 年级学生 5~8 分钟的注意力窗口。建议把"写出第一个程序 + Dev-C++ 操作"单独作为先导课，"变量、cin/cout、简单运算"作为第 02 课；并为 Dev-C++ 的"新建→保存→F11"增加截图或 GIF，降低因"找不到保存位置"导致的第一步放弃。

2. **合并或差异化第 05、06 课，避免连续重复**
   第 06 课与第 05 课内容高度重合（if-else、奇偶、倍数、`==`/`=`），小明会感到无聊、觉得课程在"水时长"。建议将两课合并为一节"分支判断"，腾出课时给后续真正需要加强的内容；如果必须保留两节，第 06 课应引入新情境或新题型（如嵌套 if、多条件组合），而不是重复同样的 demo 和 challenge。

3. **把 `break` 和 `continue` 提前做统一铺垫，并解释清楚"空条件 for 循环"**
   第 09 课在 switch 里首次出现 `break`，第 11 课才在循环里讲 `break/continue`，且第 11、12、15 课频繁使用 `for (int i = 1; ; i++)` 这种缺条件的无限循环，却未解释"空条件表示永远成立"。建议：① 第 09 课讲 switch 时只讲"case 结束要停"，避免过早使用 `break` 这个词；② 第 11 课专门用一页解释 `break` "跳出当前包裹它的结构"，并配图对比 switch 和循环；③ 任何使用 `for(;;)` 的地方都必须先解释"中间条件空着就是一直成立"。

4. **降低第 17 课 `scanf/printf` 的认知冲击，先讲"为什么"再讲规则表**
   零基础学生在 16 课刚习惯 `cin/cout`，第 17 课突然切换到完全不同的输入输出风格，且出现 `&`、 `%lf`/`%f`、 `\n` 等大量需要硬记的规则，容易造成"以前白学了"的挫败感。建议：① 先用 1~2 个卡片解释"考试需要两种写法，就像铅笔和钢笔"；② 把 `%lf` vs `%f` 的区别用一张对比表高亮；③ 第一题先用 `printf` 输出固定文字，再用 `scanf` 读一个整数，最后再引入格式化宽度，分三步递进。

5. **在算法模式课（第 10、13、15 课）增加"步骤填空"和可视化动画**
   第 10 课的"累加桶"、第 13 课的"找老大"、第 15 课的"短除法"都需要学生理解"变量在每次循环中如何变化"。当前课程只有代码示例，小明会复制但不懂。建议：① 用表格或动画展示循环每轮 `i`、`sum`、`n` 的值怎么变；② 在挑战前先出一道"补全 3 行关键代码"的半开放题，强迫学生思考而不是整段复制；③ 对 `product = 1` 这类反直觉初始值，用具体数字演示"如果从 0 开始结果会怎样"。
