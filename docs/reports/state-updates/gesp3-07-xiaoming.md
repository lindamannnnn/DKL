## 本课掌握的新概念（闭卷验证过，细节有漏洞）

- `string` 比字符数组方便：不用算格子（动机层面接受度高）
- 拼接 `+` / `+=`、比较 `==`（CP1 闭卷 ✅）
- `s.find(t)` 找首位置，下标从 0 数（CP3 闭卷 ✅）
- `s.replace(起点, 个数, 新内容)`（CP4 闭卷 ✅）
- `s.size()` 求长度（但"空格算字符"靠踩坑才记住，见下）
- 逐格遍历 + 条件拼新串（课后 4 一次 AC ✅，本课他最扎实的一项）
- find 循环计数（课后 3 ✅，但骨架源自对 demo 的模仿改造）

## 新易错点（本课实测发生）

- `size()` 漏数空格（CP2 闭卷答错；规则藏在 getline 说明里，没有针对 size 强调）
- 有空格的主串第一反应仍用 `cin >> s`（挑战 1 再踩 06 课同一坑，已是第二次）
- tolower 逐格比较时只转一边（课后 1 闭卷 `tolower(a[i]) != b[i]`，错）
- 漏写边界分支（课后 2 第一版漏"找不到输出 -1"）
- 长行代码直接放弃理解、纯抄形式（挑战 2 的 while 行，三道题抄三次仍不能独立默写）

## 仍不懂 / 不扎实的概念

- 挑战 2 的 `while ((pos = s.find(o, pos)) != string::npos)`：find 双参数、条件内赋值、npos 比较三合一，完全靠抄，**未内化**（直接导致完成度 0.7 未过线）
- `string::npos` 的 `::` 含义（当乱码硬背）
- `substr`（课后题 2 提示中出现，未学，当场烦躁）
- getline 与 `cin >>` 的选择规则：踩坑后能改对，但下次新题仍可能先选错
- 字典序的严格含义（沿用 GESP3-06 的模糊理解，本课 `a < b` 只是接受结论）
